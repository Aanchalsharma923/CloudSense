# Phase 7.1 Metric Provenance Reconciliation

## Executive Summary
A forensic audit was conducted on the apparent discrepancy between the PR-AUC metrics reported in earlier Phase 7 documents versus the Phase 7.1 Final Verification Report. 

The audit concludes that the underlying metrics calculation, model predictions, and `.csv` results are **100% scientifically valid**. 
The inconsistency was caused entirely by a **Markdown table formatting error** (a manual column-shift mistake) when rendering the final report in `docs/ml/phase7_1_final_freeze_verification.md`. 

No retraining is required. The models remain fully verified.

---

## Metric Implementation Trace

### 1. What target is used for normal occurrence PR-AUC?
`y_true_occ` (binary indicator for rainfall).

### 2. What rainfall threshold defines occurrence?
`> 0.1` mm.
*(Source: `src/ml/experiments/corrected_final_test.py`, Line 27: `y_true_occ = (y_true > 0.1).astype(int)`)*

### 3. What target is used for extreme-event PR-AUC?
`y_true_ext` (binary indicator for extreme rainfall).

### 4. What threshold defines an extreme event?
`17.9128` mm.
*(Source: `src/ml/experiments/corrected_final_test.py`, Line 11: `EXTREME_THRESHOLD = 17.9128` and Line 38: `y_true_ext = (y_true > EXTREME_THRESHOLD).astype(int)`)*

### 5. What prediction score is supplied to each PR-AUC calculation?
The raw continuous prediction output (`y_pred`) from the LightGBM Tweedie regressors is supplied as the ranking score to `average_precision_score()`. This is mathematically sound for PR-AUC.
*(Source: `src/ml/experiments/corrected_final_test.py`, Line 31 and Line 42)*

### 6. Are the reported CSV columns labelled correctly?
Yes. The script successfully outputs `pr_auc` and `ext_pr_auc` into `docs/ml/experiments/corrected_test_results.csv` with the correct values mapping to the correct columns.

### 7. Did the metric definitions change between Phase 7 and Phase 7.1?
No. The metric calculation logic remained completely unchanged. The slight numerical difference (e.g., ~0.805 -> 0.8032) is simply due to the corrected training dataset regime (2000-2018 instead of 2018-2021).

## The Origin of the Discrepancy

When rendering the table for the final verification markdown, the following raw output was generated by the validation script:

```text
 horizon      mae      rmse      bias   pr_auc  precision   recall       f1  ext_pr_auc
       1 3.486525  9.374074  0.112754 0.803210   0.393037 0.992063 0.563017    0.403685
```

Due to a formatting misalignment in the markdown generator, the columns were incorrectly shifted by one position:
- `precision` (0.3930) was pasted under `PR-AUC`.
- `recall` (0.9920) was pasted under `Precision`.
- `f1` (0.5630) was pasted under `Recall`.
- `ext_pr_auc` (0.4036) was pasted under `F1`.
- `pr_auc` (0.8032) was pasted under `Extreme PR-AUC`.
